# 独立技能的按需配合

本套以研究、写作、审读作为三个入口。各专项保持可独立维护的模块，按需要配合；本文件说明选择与交接，不复制主体规则。

| 当前委托 | 配合方式 | 不应额外启动 |
|---|---|---|
| 读懂一篇哲学或宗教学文本 | close-reading；概念关系决定读法时加 concept-work，检验推论时加 argument；关键材料未取得才加 source-discovery | 不自动重做选题或写整篇论文 |
| 从课程材料或旧论文发展问题 | question-design 配合实际需要的 source-discovery、close-reading、scholarship 或 argument，完成一次实质试探 | 不预设旧稿代表用户当前立场 |
| 完整研究与成文 | research 调度必要研究技能；writing 接续已得结果，按需 author-voice；成稿用 review，并实际读取 defensive-editing 与 ai-style-editing | 不规定所有研究必须采用同一种方法或章节 |
| 仅检查 AI 词句或防御性表达 | 对应专项；两类问题并存就合用；中文例子需要时读 humanizer-zh | 不启动全文重构、一般语病校正或检测分数优化 |
| 只按本人语气修改 | 学术用 author-voice，一般邮件与随笔用 voice-dna；只有实际模板问题才加相应编辑技能 | 不为声音模仿编造经历或固定立场 |
| 审稿／先列方案 | review；关键判断欠核实才追加所需研究专项，词句问题用相应编辑专项 | 审稿不是写回许可，已选编号不扩大 |
| 双语写作／翻译 | writing 与翻译指南；实际概念歧义再加 concept-work，要求语气适配再加 author-voice | 忠实翻译不变成删改论证 |
| 数字人文方法、语料或评估论文 | 根据贡献选 tech-paper-template 或 benchmark-paper-template，再配合必要研究与写作技能 | 普通哲学论文不套技术论文模板 |

表内简称均指 humanities- 前缀的同名技能（humanizer-zh、voice-dna 与两个 template 除外）。具体模块见研究入口的调度表。图示需要时用 figure-designer，重建已有图用 drawio-reconstruction。

同一处问题只处理一次。表达检查先辨明命题、否定与条件，再改剩余词句；出现实质解释缺口时，是否补研究由当前授权范围决定。交接沿用决定性原文、归属、模态、已得判断、未决处与冻结内容，不重复生成提纲或方法提醒。达到当前交付标准即停止追加技能。

旧名称若仍出现在历史对话中，按功能找到现有专项：vibe-research-workflow → research；idea-evaluator → question-design/argument；deep-research → source-discovery/scholarship；paper-writer 和 intro-drafter → writing；paper-polish → writing 或两类编辑专项；pre-submission-reviewer → review。旧入口已移出启用目录，不应寻找或复活历史副本来执行。
