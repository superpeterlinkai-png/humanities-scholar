# Review an existing LaTeX manuscript

Use this guide only for LaTeX-specific work. Preserve the project's document
class, engine, packages, citation commands, macros, file layout, and conventions
when they work. A review is not authorization to reorganize the repository.

Check unresolved citations and cross-references, missing assets, compilation
errors, important overflow, and rendering of scripts, diacritics, quotations, and
footnotes. Inspect the relevant source and output before proposing a repair.

Use the citation system and bibliography style required by the project or venue.
Check records against the appropriate source, not a single database mandated for
all disciplines. A book or archival reference need not have conference fields.

Keep labels unique and references consistent. Nonbreaking spaces can prevent
awkward breaks between labels and numbers; retain compatible established label
naming conventions rather than rejecting ordinary hyphens categorically.

Use vector graphics for suitable diagrams and sufficiently clear raster images
for photographs, scans, and facsimiles. Follow actual output requirements and
verify final rendering. Captions should explain the figure's role and limits.

Judge float placement, equation numbering, quotation handling, and punctuation
within the actual class, engine, language, and house style. Do not impose a universal
ban on em dashes or Unicode punctuation that the project handles correctly.

For a requested revision response, connect responses to the actual reviewer points
and changed text. Preserve established tracked-change or response conventions;
do not introduce color macros or extra response files without a task-related need.
