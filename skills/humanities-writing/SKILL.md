# 研究成文

读 [共同约定](../humanities-research/references/research-contract.md)。根据用户需要交付正文，沿用现有稿件、材料和已作判断；要全文就完成全文，要一段就只写所需段落。材料与核心论证不足时直接补做相应研究，而不是让用户先提交全部论点。

明确正文要回答的问题、允许的篇幅和证据范围。思路仍探索时写可检验的暂定论证，不冒充已定稿。适当的具体分析可以先写，以其结果调整结构；不要求先确定每个标题。

篇章依据思想推进组织：读者要先理解什么，后面的判断才成立？关键段落要让读者看到某个措辞、形式、历史关系或前提怎样支持判断。不要把“先引理论、再举例、最后说明复杂性”作为通用段落算法。引用后必须完成所需解释，而非只说“这表明”。

需要个人声音时读 [作者声音](../humanities-author-voice/SKILL.md)，利用当前样本与明示偏好。思想忠实优先于表面相似；新增解释可以写进暂定稿，但在交付说明中标出尚待用户确认的实质取舍，不把整篇变成括号和警告。

学术文类与翻译的特殊要求见 [成文与交付](references/genres-and-delivery.md)。叙述作者思想时保持归属；轮到本文主张时给出理由。不要让大师名词和引文密度替代作者自己的分析，也不要通过删光学术对话来制造“原创声音”。

完成后以读者顺序通读：引言承诺的任务是否兑现，章节是否实际增加理解，结论是否超过依据，摘要是否准确反映最终稿。检查关键引文与参考文献对应关系。缺少决定性来源时调整相关主张或准确标注，不用伪造的完整书目修饰稿件。

用户只要润色时保留结构、术语、归属、否定和模态；影响成立与否的问题可简短指出，不擅自重写立场。全文委托则完成必要实质修改，并交付可用文件或聊天正文。格式工具存在时按该格式技能制作和验证，不能把 Markdown 改后缀称为 Word。
